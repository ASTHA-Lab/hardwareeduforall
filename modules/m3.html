Timing side channel

Measure an early-exit password check on the logic analyzer, then make the comparison constant-time.

The program grants access when a typed password matches a stored one. The comparison returns at the first mismatch, so a wrong first character finishes sooner than a wrong later character. The lecture derives that dependence from CMOS switching energy, names five emissions an attacker can use, and reduces Kocher’s timing attack on exponentiation to this string comparison. The lab then measures the comparison the course can actually instrument.

Outcome

The student turns in a timing table for the vulnerable check and a second table for a comparison that always walks the whole password, and discusses whether the leak is gone. This is the only module in which the defense is measured on the same instrument as the attack.

How the time is taken

  1. Configure the UART. The starter targets 9600 baud on a 12 MHz crystal, Timer 1 in mode 2.
  2. Set the timer run bit before the password check and clear it after. Read the interval between those edges on the logic analyzer in the debugger. The handout asks for five guesses, terminated with a period.
  3. Rewrite the comparison so every character is examined regardless of the first mismatch. Repeat the five guesses on the same instrument.

A lecture demonstration, not the graded passwords

The lecture deck reports eight guesses against a demonstration password. Cycle counts rise as the matching prefix gets longer. The graded assignment uses a different password and a different list of guesses. The figure below is the lecture measurement.
